# Queue start and automatic polling

Queue 시작 시 기존 `has_requests()` 검사는 자동 polling과 사용자 요청을 구분하지
않았으므로, 실험이 없어도 자동 읽기가 대기/실행 중이면 Queue 시작이 차단됐습니다.

Queue는 `AUTO_MONITOR.workflow()` 범위에서 새 자동 읽기를 중지하고 이미 제출된
`automatic_monitor=True` 읽기가 끝나기를 최대 22초 기다립니다. 대기 중 Queue 중단은
즉시 반영됩니다. 진행 중인 읽기를 강제 취소하거나 무시하고 장비 명령을 보내지 않습니다.
자동 읽기가 실패하거나 제한 시간 내 끝나지 않으면 해당 장비·작업을 표시하고 시작하지 않습니다.

사용자 요청, 수동 Acquire, 백그라운드 실험, 반복 waveform은 계속 시작을 차단합니다.
오류에 연결 별칭, 장비 이름, family, 작업명, queued/running/stopping 상태,
request ID 및 가능한 경우 실행 위치를 표시합니다. 완료된 요청이 목록에 잠시 남아
있는 경우는 차단 대상에서 제외합니다. 실행 중인 백그라운드 작업의 종료 처리는 기다려야 합니다.

이 변경은 RE 그래프 선택과 무관합니다. RE의 표시 그래프 체크는 표시만 제어하며
측정과 결과 저장에는 영향을 주지 않습니다. 모든 항목을 체크하면 기존 전체 그래프를 표시합니다.
