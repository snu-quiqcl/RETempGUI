# 자동 상태 조회

장비별 60초 타이머는 조회 필요 여부만 등록합니다. 등록을 반복해도 장비별 한 건으로 합쳐지며,
파라미터별 MONITOR operation을 한꺼번에 큐에 넣지 않습니다.

- 동일한 서버 주소/포트에는 자동 조회 operation을 한 번에 하나만 실행합니다.
- 일반 MONITOR는 파라미터 하나씩 조회하고 장비를 번갈아 선택합니다.
- 완료 후 최소 0.5초 간격을 두며, UI 타이머가 0.2초마다 실행 가능 여부를 확인합니다.
- 기존 60초 이내 정상 관측값은 다시 조회하지 않습니다. 장비 수/작업 상태에 따라 갱신은 더 늦어질 수 있습니다.
- 사용자 workflow의 실행·대기·종료 정리 전체와 내장 scan/PID/오븐 작업, 연속 측정 중에는 자동 조회를 미룹니다.
- 수동 operation이 실행 또는 대기 중이어도 자동 조회를 미룹니다. 큐에 막 들어간 자동 조회도 실행 직전에 다시 확인합니다.
- 오븐 대기 상태의 주기적 전압·전류 readback도 같은 서버별 실행 제한을 따릅니다.
  오븐 로딩 중 workflow 자체가 수행하는 readback과 보호·종료 operation은 유지합니다.

서버 응답 timeout 발생 시 해당 서버의 자동 조회 등록을 지우고 새 자동 조회를 차단합니다.
시간이 지났다고 자동으로 재시도하지 않습니다. 메인 연결 상태에 자동 조회 중지를 표시합니다.
서버/장비 상태를 확인한 뒤 **연결 해제 → 연결**에 성공하면 자동 조회를 다시 허용합니다.
재개 후 실제 조회는 다음 등록 타이머부터 이루어집니다. 다른 종류의 자동 조회 오류는 해당 장비만 재연결까지 중지합니다.

수동 Read/Acquire, 명시적으로 호출하는 workflow `monitor()` API, 제어 명령, 오류 전파,
전류 ramp와 종료 정리는 유지합니다. 자동 조회 중지는 출력 OFF를 뜻하지 않습니다.
자동 조회를 중지한 상태에서 수동 읽기가 성공해도 자동 조회 차단은 재연결 전까지 유지합니다.

이미 전송된 조회는 강제로 끊거나 재전송하지 않습니다. Workflow 시작 직전 조회가 전송되었다면
그 한 건의 응답 또는 기존 20초 응답 제한까지 지연될 수 있습니다.
이 변경은 현재 UI 프로세스 내부의 자동 조회를 조절합니다. 다른 UI 인스턴스나 서버 자체 polling,
드라이버의 통신 정지는 별도로 확인해야 합니다.
