# FPGA 장비 창과 실험 창

## 장비 연결

메인의 **로컬 FPGA 검색 / 연결**을 누르면 FPGA 창의 고정 **장비 연결** 탭을 연다.
USB 검색 → 포트 선택 → 저장 별명 입력 → **연결하고 인스턴스 열기** 순서로 사용한다.
연결 성공 시 `별명 · FPGA ID` 탭이 생긴다. 이미 연결된 포트를 선택하면 기존 탭을 연다.
앱 시작, 전체 연결, 저장된 장비 구성 불러오기, Queue 실행은 FPGA를 자동 연결하지 않는다.

각 FPGA 탭에는 기존 색상 ON/OFF 출력 버튼, TRIGGER, Input counts와 CSV 로깅이 있다.
출력 색상은 초록 ON, 빨강 OFF, 회색 연결 안 됨/상태 미확인이다.
**핀 이름 설정…**은 별도 창으로 JA/JB/JC/JD의 32개 신호를 보여준다.
연결 중에는 핀 이름을 조회·내보내기할 수 있고, 이름 수정·불러오기는 연결 해제 후 수행한다.
slow 출력의 `*`는 실제 readback이 아닌 마지막 성공 명령값을 의미한다.
창 닫기는 숨김이며 연결 해제나 실험 중지가 아니다.

## 실험 선택

메인의 **실험 창 열기** 또는 장비 메뉴의 **실험**을 사용한다.
Scan, Daily characterization, Decay, HOM, Entanglement, Ion Check, Micromotion, etc,
Workflow가 공통 창에 모인다. 기존 실험 조건, 시퀀스, 분석 및 그래프를 유지한다.
Daily/Decay의 EA·EC 및 개별 실험 페이지도 각자 FPGA를 선택한다.

사용할 FPGA 목록은 연결된 장비만 제공한다. 이미 선택한 장비가 끊기면
`연결 끊김` 상태를 유지하며 다른 장비로 자동 전환하지 않는다.
FPGA를 바꿀 때 노출 시간·반복 횟수 등의 실험 조건은 유지한다.
핀 목록과 저장된 역할 매핑은 새 FPGA의 것으로 바꾸며, 결과 화면은 장비별로 보존한다.
각 FPGA의 기본 결과 경로는 별명을 사용한다.
저장하지 않은 역할 매핑은 전환 시 저장·버리기·취소를 선택한다.
실행 전에 변경한 역할 매핑을 저장해야 한다.

핀 이름의 `PMT`, `AOM`, `MW` 접두사는 선택 제한이 아니다. 공통 역할 매핑은
입력/출력 방향에 맞는 핀 전체를 표시한다. Fluorescence와 Rabi/Initialization/
Ramsey/SPAM의 직접 선택란도 선택한 FPGA의 `설정 이름 [신호 ID]`를 표시한다.
EA/EC는 기존 기본값이며 다른 물리 입력·출력으로 바꿀 수 있다. 변경한 선택은
조건·매핑 저장으로 해당 FPGA 설정에 저장하고 Queue에도 함께 고정한다.
카운터 없는 입력과 fast output이 필요한 시퀀스의 slow output은 이유를 표시하고
비활성화한다. 이 제한은 이름이 아닌 펌웨어 기능 및 기존 시퀀스 타이밍에 따른다.
Fluorescence는 기존과 같이 광자 계수만 하며 AOM 출력을 직접 조작하지 않는다.

한 실험은 한 FPGA를 사용한다. 다른 FPGA의 실험은 별도로 실행할 수 있다.
실행 시작 시 runner가 해당 FPGA를 점유하며, 같은 FPGA의 다른 실험과 수동 출력·계수는
거부한다. 정리까지 완료되면 점유가 해제된다. 외부 모터/DAC/RF의 실험적 공유 정책은 추가하지 않는다.

## Workflow와 Queue

Workflow 편집기의 FPGA 선택란에서 대상 한 대를 고른다.
`devices.fpga()`는 선택한 FPGA를 사용하고, `devices.fpga('fpga_2')`처럼 명시할 수도 있다.
선택과 코드가 다르거나 하나의 workflow가 다른 FPGA까지 접근하면 실행 오류가 된다.
FPGA를 사용하지 않는 장비 설정 workflow는 `FPGA 미사용`으로 실행한다.

실험 페이지의 **현재 조건으로 Queue에 추가**는 설정과 FPGA ID, 핀 매핑을 함께 고정한다.
기본 실험의 Queue 항목은 개인 workflow 예제 파일 없이도 동작한다.
Workflow 편집기에서도 현재 코드를 Queue에 추가할 수 있다.
Queue는 항목을 순차 실행하며 각 항목은 서로 다른 FPGA를 지정할 수 있다.
Queue 목록의 **실행 FPGA**, **핀 매핑** 열에서 대상과 저장 여부를 확인한다.
항목을 더블클릭하면 **실험 조건 / FPGA · 핀 설정 / Monitor** 탭으로 편집한다.
**FPGA · 핀 설정** 안에서 실행 FPGA를 선택하고 입력·출력 표의 드롭다운으로
실험 역할마다 사용할 핀을 지정한다. 이름은 선택한 FPGA의 설정 이름과 신호 ID로 표시한다.
기존 항목에 매핑이 빠졌으면 연결된 FPGA를 선택하여 적용할 때 저장한다.
FPGA를 사용하는 코드에 대상이 없으면
실행을 차단하며 `fpga_local`로 자동 대체하지 않는다.
실행 전에 대상 FPGA가 미연결/사용 중이면 Queue는 일시정지한다.
연결 또는 작업 종료 후 **계속**을 눌러 재개한다. 자동 재연결·자동 대체는 하지 않는다.
실행 중 USB 단절은 해당 실행을 실패/취소 처리하고 기존 cleanup 절차를 따른다.

**Queue 항목에 적용**은 그 항목의 실험 핀 선택과 FPGA 매핑 사본만 변경한다.
공통 FPGA 설정 파일, worker의 매핑, 다른 Queue 항목은 변경하지 않는다.
취소하면 원래 항목도 유지한다. 다른 FPGA를 처음 선택하면 해당 장비의 기본 매핑을
읽으며, 편집 중 이전 FPGA로 돌아오면 그 장비에 대해 편집하던 선택을 유지한다.
**FPGA 기본 매핑 불러오기**는 현재 연결된 장비의 매핑으로 이 항목의 편집값만 초기화한다.
기본 실험의 직접 핀 선택은 실험 설정에 저장하고, HOM 등의 역할 연결은 항목의
FPGA 매핑 사본에 저장한다. 사용자 Workflow는 사용할 실험 종류를 선택하여 역할을
편집하며, 실행 코드는 해당 실험 API를 사용해야 그 역할 매핑이 적용된다.
Queue 저장 이후 보드 핀 이름이 바뀐 경우 Queue를 중지하고 항목을 갱신해야 한다.
기존 파일에 특정 FPGA ID가 하드코딩되어 있으면 코드도 같은 대상이어야 한다.

## 로컬 설정

FPGA 별명·핀 이름·실험 매핑은 기존 `config/devices/fpga/<ID>.local.json`에 저장한다.
USB serial 식별, serial 없는 장비의 순차 ID, 기존 기본 핀 배치는 변경하지 않는다.
실험별 UI 입력은 로컬 input state에 장비별로 보존하며 Git에 포함되지 않는다.
실험 결과에는 실행 시 사용한 매핑 스냅샷을 기록한다.

실물 USB 보드를 연결하지 않은 자동 검증은 물리 출력과 배선의 검증을 대신하지 않는다.
