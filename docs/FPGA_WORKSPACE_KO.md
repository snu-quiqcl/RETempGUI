# FPGA 장비 창과 실험 창

## 장비 연결

메인의 **로컬 FPGA 검색 / 연결**을 누르면 FPGA 창의 고정 **장비 연결** 탭을 연다.
USB 검색 → 포트 선택 → 저장 별명 입력 → **연결하고 인스턴스 열기** 순서로 사용한다.
연결 성공 시 `별명 · FPGA ID` 탭이 생긴다. 이미 연결된 포트를 선택하면 기존 탭을 연다.
앱 시작, 전체 연결, 저장된 장비 구성 불러오기, Queue 실행은 FPGA를 자동 연결하지 않는다.

각 FPGA 탭에는 기존 색상 ON/OFF 출력 버튼, TRIGGER, Input counts와 CSV 로깅이 있다.
출력 색상은 초록 ON, 빨강 OFF, 회색 연결 안 됨/상태 미확인이다.
**핀 이름 설정…**은 별도 창으로 JA/JB/JC/JD의 32개 신호를 보여준다.
연결 중에는 핀 이름을 조회·내보내기할 수 있고, 이름 수정·불러오기는 연결 해제 후 수행한다.
slow 출력의 `*`는 실제 readback이 아닌 마지막 성공 명령값을 의미한다.
창 닫기는 숨김이며 연결 해제나 실험 중지가 아니다.

## 실험 선택

메인의 **실험 창 열기** 또는 장비 메뉴의 **실험**을 사용한다.
Scan, Daily characterization, Decay, HOM, Entanglement, Ion Check, Micromotion, etc,
Workflow가 공통 창에 모인다. 기존 실험 조건, 시퀀스, 분석 및 그래프를 유지한다.
Daily/Decay의 EA·EC 및 개별 실험 페이지도 각자 FPGA를 선택한다.

사용할 FPGA 목록은 연결된 장비만 제공한다. 이미 선택한 장비가 끊기면
`연결 끊김` 상태를 유지하며 다른 장비로 자동 전환하지 않는다.
FPGA를 바꿀 때 노출 시간·반복 횟수 등의 실험 조건은 유지한다.
핀 목록과 저장된 역할 매핑은 새 FPGA의 것으로 바꾸며, 결과 화면은 장비별로 보존한다.
각 FPGA의 기본 결과 경로는 별명을 사용한다.
실험 탭과 Queue는 같은 역할 → UI 닉네임 → 물리 핀 → 기능 → 사용 단계 표를 사용한다.
물리 핀·기능은 읽기 전용이고, 공통 핀 이름은 FPGA 장비 창에서만 바꾼다.
현재 실험·챔버·모드·옵션의 실제 측정 및 시작·종료 출력만 표시한다.
Fluorescence/Scan은 PMT만, Decay 174 single은 PMT1·SYNC·AOM·TRIG만
표시하며 활성 AUX는 추가한다. HOM AOMB와 Ion Check PMT2는 사용 시에만 표시한다.
Micromotion Signal은 counter 하나, correlation/2D/Two-RF는 SYNC·PMT 두 개다.
MW 게이트는 slow output만 허용한다.

매핑의 기준 저장 위치는 labremote/config/operations/fpga/<FPGA ID>/<실험>/<파일>.json이다.
그 JSON의 fpga_mapping.signals에는 시퀀서 역할별 **공통 닉네임**을 저장한다.
사용하지 않는 모드의 기존 값은 보존하며 현재 실행에는 요구하지 않는다.
미지정 매핑도 편집 상태로 저장할 수 있고, 실행 시 사용 핀의 기능·중복을 검사한다.
매핑 변경은 로컬 설정에 자동 저장한다. Queue 편집은 해당 Queue 항목 사본만 바꾼다.

이전 devices/fpga/settings/<ID>/role_bindings.json, 구형 실험 JSON 및 UI 입력 상태는
이전 입력으로만 읽는다. 기존 역할을 해당 PC의 닉네임으로 해석하며 물리 배선을 추측하지 않는다.
원본은 labremote/data/config_backups/fpga_mapping/에 바이트 그대로 백업한다.
이전이 끝난 매핑은 UI 상태에서 중복 저장하지 않는다. 새 코드로 다른 PC를 업데이트할 때도
그 PC의 config를 유지한 채 실행해야 하며, 다른 PC의 config로 덮어쓰면 안 된다.
이전 전 원본 파일은 복구용으로 유지한다. 파일을 직접 편집한 경우 열린 탭을 다시 불러온다.

한 실험은 한 FPGA를 사용한다. 다른 FPGA의 실험은 별도로 실행할 수 있다.
실행 시작 시 runner가 해당 FPGA를 점유하며, 같은 FPGA의 다른 실험과 수동 출력·계수는
거부한다. 정리까지 완료되면 점유가 해제된다. 외부 모터/DAC/RF의 실험적 공유 정책은 추가하지 않는다.

## Workflow와 Queue

Workflow 편집기의 FPGA 선택란에서 대상 한 대를 고른다.
`devices.fpga()`는 선택한 FPGA를 사용하고, `devices.fpga('fpga_2')`처럼 명시할 수도 있다.
선택과 코드가 다르거나 하나의 workflow가 다른 FPGA까지 접근하면 실행 오류가 된다.
FPGA를 사용하지 않는 장비 설정 workflow는 `FPGA 미사용`으로 실행한다.

실험 페이지의 **현재 조건으로 Queue에 추가**는 설정과 FPGA ID, 핀 매핑을 함께 고정한다.
기본 실험의 Queue 항목은 개인 workflow 예제 파일 없이도 동작한다.
Workflow 편집기에서도 현재 코드를 Queue에 추가할 수 있다.
Queue는 항목을 순차 실행하며 각 항목은 서로 다른 FPGA를 지정할 수 있다.
**복제**는 선택한 Workflow 또는 Repeat Group 전체를 바로 다음 위치에 복사한다.
이름, 반복, 실패 정책, Python 소스, 모든 실험 조건, FPGA ID와 핀 매핑,
calibration 내용, Monitor 설정을 그대로 보존한다. 각도나 basis를 자동 변경하지 않는다.
실행 기록을 구분하는 내부 ID만 새로 만들며, 복사본 편집은 원본에 영향을 주지 않는다.
Queue 목록의 **실행 FPGA**, **핀 매핑** 열에서 대상과 저장 여부를 확인한다.
항목을 더블클릭하면 **실험 조건 / FPGA · 핀 설정 / Monitor** 탭으로 편집한다.
**FPGA · 핀 설정** 안에서 실행 FPGA를 선택하고 입력·출력 표의 드롭다운으로
실험 역할마다 사용할 핀을 지정한다. 이름은 선택한 FPGA의 설정 이름과 신호 ID로 표시한다.
기존 항목에 매핑이 빠졌으면 연결된 FPGA를 선택하여 적용할 때 저장한다.
FPGA를 사용하는 코드에 대상이 없으면
실행을 차단하며 `fpga_local`로 자동 대체하지 않는다.
실행 전에 대상 FPGA가 미연결/사용 중이면 Queue는 일시정지한다.
연결 또는 작업 종료 후 **계속**을 눌러 재개한다. 자동 재연결·자동 대체는 하지 않는다.
출력 변경·연결 후 UI 자동 REFRESH는 실험 점유와 구분한다. 이미 진행 중인
자동 조회는 완료를 기다린 뒤 다음 Workflow를 자동 실행하며, 실험 점유 중에는
새 자동 조회를 미루거나 생략한다. 다른 실험 또는 일반 작업 점유는 계속 일시정지하고
대기 사유에 점유자/작업명을 표시한다. 조회 중 통신 오류가 나면 다음 실험을 실행하지 않는다.
실행 중 USB 단절은 해당 실행을 실패/취소 처리하고 기존 cleanup 절차를 따른다.

**Queue 항목에 적용**은 그 항목의 실험 설정과 FPGA 매핑 사본만 변경한다.
공통 FPGA 설정 파일, worker의 매핑, 다른 Queue 항목은 변경하지 않는다.
취소하면 원래 항목도 유지한다. 실행 FPGA를 바꾸면 해당 보드의 공통 닉네임과
기능으로 선택값을 다시 검사하며, 대응하지 않는 이름을 임의 핀으로 바꾸지 않는다.
기본 실험은 실험 탭과 동일한 fpga_mapping 블록을 Queue 설정 사본에 저장한다.
사용자 Workflow는 parameters.mapping_experiments에 사용할 실험과 설정을 명시해야
해당 역할만 표시한다. 명시가 없으면 전체 역할 목록을 대신 표시하지 않는다.
실행 코드는 그 설정을 해당 실험 API에 전달해야 한다.
Queue 저장 이후 보드 핀 이름이 바뀐 경우 Queue를 중지하고 항목을 갱신해야 한다.
기존 파일에 특정 FPGA ID가 하드코딩되어 있으면 코드도 같은 대상이어야 한다.

### Setup 및 Ion Check

Setup에는 사용자 Workflow의 실험별 역할 매핑을 표시하지 않는다.
실험 조건의 장비·파라미터 행에서 지정한 FPGA를 실행 대상으로 사용한다.
한 Setup 항목에 FPGA 두 대를 지정할 수 없으며, 필요한 경우 Queue 항목을 나눈다.
FPGA가 없는 Setup은 다른 장비 설정만 실행한다.

Ion Check Queue 항목의 PMT 입력 1/2와 Laser A/B/C는 **FPGA · 핀 설정**에서
실제 FPGA 핀 이름으로 선택한다. PMT 입력 2는 사용하지 않을 수 있다.
시퀀서가 함께 조작하는 EOM 7GA/7GC, EOM 2GA/2GC, MW A/C도 같은 표에 표시한다.
사용하지 않는 SYNC/TRIG 역할은 표시하지 않는다. 기존 설정 파일은 계속 불러올 수 있다.
실험창에서는 채널 선택을 측정 조건과 분리된 입력·출력 핀 설정 영역으로 옮겼으며,
역할 매핑에는 선택한 채널과 실제 사용되는 고정 출력만 표시한다.
Ion Check 시퀀서와 종료 출력 상태는 변경하지 않았다.

### Phase shifter 위상 고정 Workflow

Queue의 Workflow 추가에서 `labremote/workflow/phase_hold.py`를 불러온다.
편집 탭은 **실험 조건 / FPGA · 핀 설정 / Monitor / JSON · 고급 편집**이다.

- 실험 조건: 연결된 실행 FPGA, 고정할 위상(0~360°), calibration 파일을 선택한다.
  기존 실험창의 Ramsey JSON 보간 또는 CSV 보정표 기능을 그대로 사용한다.
  CSV의 지원 각도 제한도 기존과 같다. 보정 없는 모드도 사용할 수 있다.
- FPGA · 핀 설정: D0~D11 순서로 서로 다른 slow output 12개를 지정한다.
  새 Workflow는 실제 배선을 가정하지 않으므로 최초 핀 지정이 필요하다.
  실험창에서 저장한 위상 고정 설정 JSON을 불러올 수도 있다.
- Monitor: 기존 Queue 모니터 설정을 사용한다. 기본은 없음이며,
  실행 결과에는 요청 각도, 적용 추정 각도, 출력 코드가 기록된다.
- JSON: 현재 항목의 조건과 calibration 스냅샷을 확인·편집한다.

보정 파일의 내용과 해시를 항목에 저장하므로 원본 파일의 변경·이동에 영향을 받지 않는다.
실행은 기존 위상 고정 API를 사용하고 FPGA 점유 규칙을 따른다.
위상 출력은 다음 변경 명령 또는 FPGA 리셋까지 유지되며, 자동으로 0°로 되돌리지 않는다.
표시하는 적용 각도는 보정 모델의 추정값이며 실제 위상 readback은 아니다.

## 로컬 설정

FPGA 별명·공통 핀 이름은 config/devices/fpga/<ID>.json에 저장한다.
실험 매핑은 config/operations/fpga/<ID>/<실험>/<파일>.json에만 저장한다.
USB serial 식별, serial 없는 장비의 순차 ID, 기존 기본 핀 배치는 변경하지 않는다.
매핑 이외의 실험별 UI 입력은 로컬 input state에 장비별로 보존하며 Git에 포함되지 않는다.
실험 결과에는 실행 시 사용한 매핑 스냅샷을 기록한다.

실물 USB 보드를 연결하지 않은 자동 검증은 물리 출력과 배선의 검증을 대신하지 않는다.

## Queue 결과 폴더

새 Queue 실행은 `groups/<그룹 이름>/<항목 이름>/repeat_0001/`에 단계별 파일과
개별 실험 결과를 저장한다. 반복 그룹의 회차가 repeat 번호가 된다.
그룹 없는 항목은 `groups/Ungrouped/<항목 이름>/repeat_0001/`을 사용한다.
Queue 전체 반복이 2회 이상이면 그룹 폴더 아래, 항목 폴더 위에
`queue_repeat_0001/`을 추가한다. 그룹 안의 항목 자체도 반복한다면
`repeat_0001/run_0001/`로 구분하여 결과를 덮어쓰지 않는다.

그룹·항목 이름은 실행 시작 시 고정된다. Windows에서 사용할 수 없는 문자는
밑줄로 바꾸고, 빈 이름과 예약 이름을 처리한다. 이름은 최대 60자로 줄이며
같은 위치의 중복 이름(대소문자 차이 포함)은 `__02`, `__03` 등을 붙인다.
원래 이름과 step ID는 manifest에 그대로 남는다.
`directory`와 `result_file`은 Queue 폴더 기준 상대 경로다.
미실행·Skip 항목의 결과 폴더는 만들지 않는다.

기존 `steps/step_000001/` 데이터와 저장된 Queue 설정은 변환 없이 계속 읽는다.
모니터는 폴더 이름을 추측하지 않고 manifest에 기록된 경로를 사용한다.
개별 실험의 FPGA 별명 하위 폴더, 데이터 형식, 핀 매핑 스냅샷은 유지한다.

Queue 실행 폴더는 `YYMMDD_HHMMSS_<8자리 ID>`로 저장한다. 그 안의 기본 실험
runner가 만드는 결과 폴더는 `r_<8자리 ID>`로 줄인다. 그룹·항목·회차 및 FPGA
별명은 유지하며, 전체 Queue UUID는 manifest의 `run_uuid`, 실험 request ID와
설정은 기존 결과 JSON에 기록한다. 같은 workflow에서 실험을 여러 번 호출해도
각 결과 폴더를 별도로 만들며 기존 파일을 덮어쓰지 않는다. 단독 실험 이름은 유지한다.

Queue 시작 전에 모든 단계의 경로 길이를 검사한다. 소스 백업·임시 JSON 파일,
EA/EC 하위 폴더와 FPGA 별명의 길이를 고려하고, Windows의 긴 경로 설정과 무관하게
259 UTF-16 코드 단위 이내를 기준으로 한다. 여유가 부족하면 장비 명령 실행과
Queue 폴더 생성 전에 오류를 표시한다. 저장 위치를 `C:\QData`처럼 짧게 지정하거나
그룹·항목·별명을 줄이면 된다. 이전 폴더는 이름을 바꾸거나 이동하지 않는다.
사용자 workflow가 직접 만드는 임의의 하위 경로·외부 저장 경로는 정적으로 예측할 수
없다. 기본 runner는 실제 결과 폴더를 만들기 전에도 길이를 다시 검사한다.

## 화면 너비와 탭 스크롤

실험·장비·Queue의 탭은 각각 독립적인 스크롤 영역을 사용한다. 다른 탭의 긴
문구나 큰 그래프가 현재 탭의 너비를 늘리지 않는다. 큰 그래프나 고정 폭 장비
표의 가로 스크롤은 해당 탭 안에만 표시된다.
실행·중단 및 주요 연결 버튼은 좁은 화면에서 여러 줄로 배치하며,
연결 상태·오류 문구는 줄바꿈한다. 긴 FPGA 이름과 핀 이름은 선택창을
과도하게 넓히지 않으며 선택 목록과 툴팁으로 전체 이름을 확인할 수 있다.
탭의 선택 대상, 버튼 동작, 입력값과 로컬 설정 파일 형식은 유지한다.

## 결과 저장 및 실시간 그래프

결과 JSON은 고유 임시 파일에 완전히 기록한 뒤 교체한다. 앱 내부 모니터 읽기와
저장을 조정하고, 외부 프로그램의 일시적인 파일 점유에는 제한적으로 재시도한다.
지속적인 저장 실패는 오류로 보고하며 마지막 정상 파일과 복구용 임시 파일을 보존한다.
기존 결과 형식과 원시 데이터, 측정 및 체크포인트 시점은 유지한다.

얽힘 실시간 그래프의 decay 피팅은 백그라운드에서 계산한다. 숨겨진 그래프는
그리지 않고 최신 데이터를 보관하며, 표시 중에는 1초 주기로 준비된 결과를 반영한다.
이전 표시를 계산하는 동안 들어온 중간 화면 갱신은 합쳐지지만 저장 데이터는 생략하지 않는다.
